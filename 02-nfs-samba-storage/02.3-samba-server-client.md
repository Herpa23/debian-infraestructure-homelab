
# Módulo 02: Almacenamiento en Red - Samba (SMB/CIFS) 

Este documento detalla la instalación, configuración y acceso al servicio de almacenamiento compartido mediante **Samba** en la máquina virtual `debian-infra`. A diferencia de NFS, Samba está diseñado específicamente para ofrecer compatibilidad nativa con sistemas operativos Windows (como el equipo host del homelab), utilizando un modelo de autenticación basado en usuarios y contraseñas propias del servicio. ---

## 1. Instalación de Paquetes de Samba

En la máquina virtual `debian-infra`, se actualizó el índice de paquetes y se instaló el demonio principal de Samba junto con sus utilidades de gestión: 

```bash 
sudo apt update sudo apt install samba smbclient -y
```


Una vez instalado, se verificó que el servicio estuviera activo y habilitado para iniciar automáticamente con el sistema:

```bash
sudo systemctl status smbd
```

## 2. Creación del Directorio Compartido y Estructura de Permisos

Para mantener una arquitectura limpia y separada de los servicios del sistema operativo, se creó un directorio dedicado al almacenamiento Samba en `/srv`:

- **Creación del directorio:**

    ```bash
    sudo mkdir -p /srv/samba/shared
    ```
    
- **Configuración de la propiedad y permisos colaborativos:** Al igual que en NFS, se asignó una estructura segura para garantizar que los archivos creados mantengan consistencia de acceso:

    ```bash
    sudo chown -R root:nogroup /srv/samba/shared
    sudo chmod 2775 /srv/samba/shared
    ```

(Nota: El bit SetGID `2` asegura que los nuevos archivos y carpetas creados dentro del recurso hereden automáticamente la pertenencia al grupo del directorio).


- **Creación de un usuario dedicado al sistema (si no existe previamente):**

    ```bash
    sudo useradd -M -s /sbin/nologin smbuser
    ```

(Nota: La bandera `-M` evita que se cree un directorio home innecesario y `-s /sbin/nologin` bloquea el acceso por SSH o shell interactiva por motivos de seguridad)._

- **Asignación de contraseña para el servicio Samba:**


    ```
    sudo smbpasswd -a smbuser
    ```
(Se ingresa y confirma la contraseña segura que el cliente utilizará al conectarse desde Windows)._

- **Habilitación de la cuenta en Samba:**

    ```bash
   sudo smbpasswd -enable smbuser
    ```


## 3. Configuración del Archivo Maestro (`/smb.conf`)

Para definir los recursos compartidos y sus reglas de acceso, se editó el archivo de configuración principal de Samba:

Bash

```
sudo nano /etc/samba/smb.conf
```

Se añadió al final del archivo el siguiente bloque de definición para el recurso compartido:

Ini, TOML

```
[shared]
   path = /srv/samba/shared
   browsable = yes
   read only = no
   guest ok = no
   valid users = smbuser
```

### Desglose de Parámetros del Recurso (`smb.conf`):

- **`path`**: Ruta absoluta en el servidor Debian donde se alojan los archivos compartidos.
    
- **`browsable = yes`**: Permite que el recurso sea visible al explorar la red desde equipos Windows.
    
- **`read only = no`**: Concede permisos de escritura (su valor predeterminado es `yes`, por lo que debe desactivarse explícitamente para permitir la subida de archivos).
    
- **`guest ok = no`**: Prohíbe el acceso anónimo; obliga a autenticarse obligatoriamente con credenciales válidas.
    
- **`valid users = smbuser`**: Restringe el acceso de lectura y escritura exclusivamente al usuario autorizado.


Una vez guardados los cambios, se validó la sintaxis general del archivo ejecutando:

Bash

```
testparm
```

Y se reinició el servicio para aplicar la nueva configuración:

Bash

```
sudo systemctl restart smbd
```


## 4. Apertura de Puertos en UFW para Samba

Para permitir el tráfico de red necesario para la autenticación y transferencia de archivos SMB sin abrir puertos arbitrarios, se utilizó el perfil integrado de UFW:

1. **Aplicación de la regla de cortafuegos:**
    
    ```bash
    sudo ufw allow in from 192.168.56.0/24 to 192.168.56.10 app Samba
    ```
    
2. **Verificación de la regla aplicada:**

    ```bash
    sudo ufw status verbose
    ```

(Se comprobará que el puerto `445/tcp` y los servicios asociados de NetBIOS queden correctamente habilitados exclusivamente para la subred del homelab).


### 6. Conexión y Mapeo desde el Cliente Windows (PowerShell)

A diferencia de Linux, el cliente nativo de Windows (SMB) suele presentar restricciones de seguridad estrictas ante credenciales almacenadas o bloqueos de autenticación anónima cuando se intenta conectar por interfaz gráfica. 
Para evitar estos inconvenientes y garantizar un enlace persistente y directo, se recomienda realizar el mapeo de la unidad de red mediante **PowerShell** utilizando el comando `net use`.
#### A. Comando de Mapeo de Unidad de Red

Abrir una terminal de **PowerShell** en el equipo host de Windows con privilegios estándar y ejecutar la siguiente instrucción (reemplazando `smbuser` por el usuario configurado y asignándole una letra de unidad libre, por ejemplo, `Z:`): 

```powershell 
net use Z: \\192.168.56.10\shared /user:smbuser
```

Al presionar **Enter**, la consola solicitará de manera segura la contraseña correspondiente al usuario de Samba (`smbuser`). Una vez introducida de forma correcta, se establecerá el canal de comunicación cifrado.

#### B. Anatomía de la Ruta de Red que usamos (Formato UNC)

A diferencia de Linux, donde los recursos montados se integran dentro de un árbol de directorios estándar con barras normales (`/mnt/...`), el sistema operativo Windows utiliza el estándar **UNC (Universal Naming Convention)** para localizar recursos compartidos a través de la red local. 

La estructura utilizada en el comando (`\\192.168.56.10\shared`) se compone de tres elementos clave: 
1. **Las barras invertidas dobles (`\\`):** Indican al sistema operativo Windows que se va a realizar una consulta o conexión hacia un recurso de red externo utilizando el protocolo SMB, en lugar de buscar una ruta o disco local dentro de la propia computadora. 
2. **La dirección IP del servidor (`192.168.56.10`):** Especifica la máquina host o servidor Debian exacto dentro de la red local (homelab) al cual nos queremos conectar. 
3. **El nombre del recurso compartido (`\shared`):** Corresponde estrictamente al identificador o nombre que se configuró entre corchetes dentro del archivo maestro de Samba (`/etc/samba/smb.conf`). * *Nota:* Si en lugar de `[shared]` hubieras definido el bloque como `[homelab-repo]`, la ruta de acceso en el cliente Windows pasaría a ser obligatoriamente `\\192.168.56.10\homelab-repo`. El nombre debe coincidir letra por letra con el definido en el servidor.
#### C. Verificación del Mapeo Exitoso

Para comprobar que la unidad de red quedó correctamente enlazada al sistema de archivos de Windows, puedes verificar las unidades conectadas ejecutando:

PowerShell

```
net use
```

O simplemente abriendo el **Explorador de Archivos**, donde aparecerá la nueva unidad `Z:` lista para interactuar con lectura y escritura directa sobre el servidor Debian.

#### D. Desconexión del Recurso Compartido (Opcional)

Si en algún momento necesitas liberar la unidad mapeada, puedes desmontarla ejecutando:

```powershell
net use Z: /delete
```
